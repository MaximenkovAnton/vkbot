# Карта возможностей VK Bot

VK-бот — один деплой (`:src:app`), который принимает события сообщества VK через Bots Long Poll, хранит
переписку, решает, нужен ли AI-ответ, генерирует его и отправляет в VK, а на длинных обсуждениях делает
саммаризацию. Карта — продуктовый рекорд, написанный из кода: строка на возможность, дальше файл
возможности со статусом, точками входа, данными, отношениями владения, ADR, acceptance criteria и тестами.

Карту проверяет [`./scripts/check-capabilities.sh`](../../scripts/check-capabilities.sh); тот же чек входит в `check` задачей
`./gradlew capabilitiesCheck` и в CI джобом `docs`. Чек падает, если в индексе или в capability-файле
указан несуществующий путь кода, acceptance criterion не находит свой тест, `ADR NNNN` не резолвится,
статус вне `planned`/`delivered`/`deprecated`, id не совпадает с именем файла или файл возможности не
указан в индексе.

## Пути пользователя (journeys)

| Journey | Шаги |
|---|---|
| `journey-answer` — «Диалог с ботом»: участник пишет боту, бот отвечает в чате | `vk-long-poll` → `message-storage` → `answer-decision` → `ai-answer` → `vk-message-send`; транспорт событий — `event-dispatch`, имена участников даёт `vk-profiles`, веб-поиск внутри ответа — `ai-tools-vane` |
| `journey-summary` — «Итог обсуждения»: бот подводит итог переписки и присылает его с forward-блоком | `message-storage` → `conversation-summary` → `vk-message-send`; транспорт событий — `event-dispatch` |
| `journey-stored-data` — «Сохранённые данные по запросу»: внешний клиент читает переписку, саммари, профили (человеческие `details`), историю изменений профиля и статистику автора | `message-storage` (REST `/persistence/*`) |
| `journey-greetings` — «Поздравления по календарю»: по cron `greetings.cron` (по умолчанию 00:00) бот поздравляет чаты с праздниками, днями рождения из VK и подтверждённым днём рождения из чата | `daily-greetings`: `message-storage` (чаты, профили, claim) + `user-knowledge` (`FindUserBirthdayFactsPort`, скрытый ДР) → `ai-answer` (текст) → `vk-message-send` (плоская отправка); запускается планировщиком, без события RabbitMQ |
| `journey-news-digest` — «Что нового»: участник спрашивает, что происходило в чате за срок; бот отвечает LLM-сводкой из сохранённых сообщений и саммари, опционально персонализированной интересами автора и темами чата | `answer-decision` (ветка `news`) → `chat-news-digest` (читает `message-storage`, опционально `user-knowledge` через `FindUserKnowledgePort`/`FindChatKnowledgeSummaryPort` — R4c) → `vk-message-send`; транспорт событий — `event-dispatch` |
| `journey-profile` — «Профиль»: участник спрашивает, что известно о человеке или группе; бот отвечает человекочитаемым досье из сохранённого профиля VK, знаний из чата (секция `Из общения:`), материализованной статистики и истории изменений | `answer-decision` (ветка `profile`) → `profile-dossier` (читает `message-storage`, `vk-profiles`, `user-knowledge`) → `vk-message-send`; транспорт событий — `event-dispatch` |
| `journey-knowledge` — «Знания из чата»: по входящим сообщениям бот извлекает факты о людях с источником, датой и доверием, хранит их и использует в досье, ответах, новостях и поздравлениях — **сквозной сценарий принят**: `AC-E2E-1` зелёный (11/11 e2e, гейт `74304c24`; полный `./gradlew build` — гейт `cb501325`) | `message-storage` → `event-dispatch` → `user-knowledge` (извлечение фактов LLM — доставлено R2a, сводка профиля и чата — R3a/R3b, чтение знаний через `FindUserKnowledgePort` — R2b/R3b; чтение birthday-фактов через `FindUserBirthdayFactsPort` — R5) → использование в `daily-greetings` (R5, delivered) и `profile-dossier` (R4a, delivered: секция `Из общения:`) / `ai-answer` (R4b, delivered: блок `[USER_KNOWLEDGE]` по знаниям автора) / `chat-news-digest` (R4c, delivered: секции «Интересы автора запроса»/«Темы чата») |
